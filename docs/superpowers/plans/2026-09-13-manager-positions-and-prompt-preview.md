## Design and acceptance

- Position.managerPositionId determines eligible direct supervisors. Head positions derive it from the company's active Boss position. Boss has no manager position. Staff choose one active, same-company, non-self occupant of their manager position; nobody else appears. A vacant/missing manager position has no eligible candidate and is shown explicitly, never silently replaced by all Agents.
- Agent position changes preserve a still-eligible current supervisor; one eligible candidate may be auto-selected; multiple candidates require an explicit choice submitted with the assignment. Changing an occupied Position's manager definition reconciles occupants transactionally: preserve eligible supervisors, select a sole candidate, otherwise clear the supervisor to a visible unconfigured state so the user can choose afterwards. Vacancies may remain visibly unconfigured, but an invalid non-null supervisor cannot be saved. Prevent Agent/Position cycles and protect these rules in API/database, including concurrent updates.
- Existing valid Staff edges are preserved during migration: when a legacy Position's assigned Agents consistently report to a different manager Position, infer and record that relationship rather than clearing those edges. In particular Internship must point to Senior Engineer because Digby reports to Ribel. Ambiguous occupied legacy relationships require diagnostics, not guessing.
- Add explicit `isCompanyLeadership` on Positions. Boss implies this flag; company-direct Staff use it with rank 2–9 and no department, without acquiring Boss authority. Heads cannot use it. Unique active Boss and Head constraints remain. Leadership displays outside department boxes and outside Unassigned; its rail item shows two lines and an Agent count.
- Department tabs ordered Settings, Goals, Members, Positions. Settings/goals are separate panels, removed from Members. Leadership has members and positions; no fake editable department record. Remove the Department select from scoped Position Editor; show textual scope if useful.
- Agent management gets a clearly named Full prompt preview action. A dialog has New task / Direct Chat modes, optional same-company project, task title/body or chat input, and a full scrollable/copyable preview. Reuse real prompt builders including company/role/position/docs/reference/operation context and adapter envelope; do not synthesize a different simplified prompt. Show this is a fresh invocation, not a continuation. Runtime-owned Hermes instructions are outside MegaCorps preview and must be identified as such. Credentials are redacted using existing sanitizers.
- Proposed read-only-computation API: POST `/api/agents/:id/prompt-preview`, body `{kind:'task'|'chat',projectId?:uuid|null,title?:string,body:string}`; response `{kind,prompt,generatedAt,redacted:true,contextMode:'full_bootstrap',...}`. It must not create cards/chat sessions/runs, dispatch adapters, rotate/create tokens, provision repos, log fake dispatches or consume model budget. Authenticate human user and company scope; reject foreign projects. Document API.
