# A2A Polling Implementation Plan

> **For agentic workers:** Use subagent-driven-development for independent transport and chat units; integrate persistence and review each result in this task.

**Goal:** Receive long A2A results without resubmitting work after HTTP timeout, including responsive durable Direct Chat.

**Architecture:** A pure polling engine consumes an atomic durable store; the production adapter supplies a PostgreSQL store. The existing result pipeline remains authoritative. Chat uses durable leased jobs and a stable execution key per user message, returning 202 while its worker waits.

**Tech Stack:** Existing Node 22, TypeScript, Fastify, PostgreSQL/Drizzle, React/Next and node:test; no added runtime package.
